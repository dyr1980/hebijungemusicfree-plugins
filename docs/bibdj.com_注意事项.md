# bibdj.com 接入注意事项（避坑清单）

> 分析时间：2026-08-09
> 分析对象：`https://www.bibdj.com/play/{id}.html`
> 用途：AjunDJ 接入该音源时的注意事项，全部基于实测（curl 直连 + 边缘节点探测）
> 合规提醒：第三方 DJ 分享站，聚合音源前请确认授权与版权，仅做个人播放/学习用途

---

## 0. 已验证的架构事实（理解注意事项的前提）

| 项 | 结论（实测） |
|----|--------------|
| 详情页 | `www.bibdj.com` → CNAME `*.cdn1cdn1.com`（CDN），**10+ 边缘节点**，openresty 反向代理 → **PHP 5.6 源站** |
| 音频主机 | `down.bibdj.com` 是**单 IP 源站**（`103.52.152.161`），不是多节点 CDN |
| 播放链路 | 详情页 SSR 内联 `var playurl = "https://down.bibdj.com/d/.../歌名.mp3"` → 请求该地址 → **302 跳转** → 阿里云 OSS 签名地址 → `audio/mpeg` 直出 |
| 真实音频托管 | 阿里云 OSS：`teambition-file.oss-cn-zhangjiakou.aliyuncs.com`，带 `OSSAccessKeyId` / `Expires` / `Signature` / `tb-file-token`（JWT） |
| 防盗链 | 音频 302 **不校验 Referer**（带/错/不带均 302）；详情页需正常浏览器 UA |

---

## 1. 502 是常态性瞬态，别当永久故障 ⚠️

- **根因（实测）**：你的 IP 被 CDN 按亲和路由钉在某个「坏/慢边缘节点」或「回源超时源站」上，所以**单 IP 稳定 502**；别的 IP 分到健康节点就是 200。直连 10 个边缘 IP，其中 `45.125.35.226` 直接连不上（`000`）。
- **不是限流**：低频率单 IP 不会被拦（实测 12 连发全 200），所以「我一个 IP 怎么 502」是节点问题，不是请求量问题。
- **应对**：遇到 `502 / 503 / 000` 一律按**瞬态**处理 → **指数退避重试 + 抖动**；重试必须**重新 DNS 解析**（别把 `www.bibdj.com` 钉死到某一个 IP），多试几次就会命中健康边缘。

## 2. 音频直链有时效，禁止长期缓存 ⚠️

- `down.bibdj.com` 返回 302 到 OSS **签名 URL**，带 `Expires` / `Signature` / `tb-file-token`，**约 1 天有效窗口**。
- **只能缓存 `playurl`（即 `down.bibdj.com/...mp3` 这段）**；每次真正播放时重新走 302 拿新的签名 OSS URL。
- 直接缓存 OSS 那条长 URL 会过期 → 播放失败 / 403。

## 3. 源站很慢，客户端超时设大 ⚠️

- 详情页响应耗时实测 **1.4s ~ 23.6s** 剧烈抖动，响应头常 `x-cache: UPDATING / EXPIRED`（频繁回源）。
- openresty 上游超时也会表现为 502。客户端**读超时建议 ≥ 30s**，并配合上面的重试。

## 4. 控制 QPS，别把边缘/源站打挂 ⚠️

- 单 IP 低频率不会限流，但**高 QPS 预加载 / 自动下一首 / 502 后疯狂重试**会形成雪崩，把边缘或源站打挂。
- 只预加载「**当前 + 下一首**」；502 后走指数退避，**不要硬重试成风暴**。

## 5. UA / Referer 处理

- 详情页需要正常浏览器 UA（伪装成 Chrome 等），否则可能被拦。
- 音频 302 本身不校验 Referer，但统一带上 `Referer: https://www.bibdj.com/` 更稳，建议所有请求都带。

## 6. 取流字段提取（已验证部分）

| 字段 | 来源 / 提取方式 | 状态 |
|------|----------------|------|
| 歌曲 ID | URL `play/{id}.html` → `play/(\d+)`；或页面 `PHPSESSID` 会话无关 | ✅ 已验证 |
| 播放直链 | 详情页 HTML 正则 `var playurl\s*=\s*["']([^"']+)["']` → 得到 `down.bibdj.com` 地址 | ✅ 已验证 |
| 音频最终地址 | 对 `playurl` 发请求 **跟随 302** 得到 OSS 签名 URL（每次现取） | ✅ 已验证 |
| 歌曲名 | 页面 `<title>`（含「歌手-歌名 - 宝贝Dj音乐网」后缀，需去后缀） | ✅ 已验证 |
| 歌手 / 封面 / 文件大小 / 播放时长 | 列表/详情页其它节点（本次未深扒） | ⏳ 待补 |

## 7. 接入 checklist（落地要点）

1. 详情页 `GET /play/{id}.html`（浏览器 UA）→ 正则取 `var playurl`。
2. 对 `playurl` 发请求 **允许跟随 302** → 得到 OSS 签名 URL → 直接播 / 下载。
3. 遇 `502/503/000` → 退避重试 + 重新 DNS 解析；读超时 ≥ 30s。
4. 不缓存 OSS URL，只缓存 `playurl`，播放时现 302。
5. QPS 克制：仅预加载当前 + 下一首；避免重试风暴。
6. 统一带 `Referer: https://www.bibdj.com/`。
7. 列表/搜索页的歌手、封面、大小、时长提取——接入时另行分析补充（见 §6 待补项）。
